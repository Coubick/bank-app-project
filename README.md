# Учбеный проект приложение-банк
## 📋Общее описание:
Приложение написано на Java с использованием микросервисной архитектуры. Проект демонстрирует работу современных Enterprise-технологий в распределенной системе. 
## ⚙️Технологии:
- Java 21
- Spring Boot 3 - основной фреймворк
- Spring Security - аутентификация и авторизация (JWT)
- Apache Kafka - брокер сообщений для событийной архитектуры
- PostgreSQL - реляционная база данных
- Docker - контейнеризация Kafka и Zookeeper
- Swagger UI, Postman - для REST API
- Maven - управление зависимостями
  
## Архитектура проекта
### Проект состоит из 5 основных модулей:
- APIGateway - единая точка входа, аутентификация, маршрутизация
- BusinessLogic - ядро бизнес-логики, обработка событий
- DataStorage - доступ к данным, репозитории
- Presentation - REST API контроллеры, DTO, документация
- Storage - сервис для сохранения событий в БД

 ## Реализованный функционал:
 - 2 роли: пользователь и администратор;
 - Клиенты с обеими ролями могут выполнить вход и выход со своего аккаунта.
### Функционал, доступный пользователю:
- Вывод информации о себе
- Пополнение счёта;
- Снятие денег со счёта;
- Получение данных о своих счетах (выводится список с номером счёта и балансом);
- Добавление в друзья других пользователей;
- Удаление из друзей;
- Вывод списка друзей с их счетами;
- Перевод средств: между своими счетами, на счёт друга, на счёт незнакомого пользователя. Для каждого из переводов предусмотрена "комиссия": 0%, 3% и 10% соответственно.
### Функционал, доступный администратору:
- Создание пользователя (пока что не реализован функционал, позволяющий пользователю создать аккаунт самому себе. Аккаунты может создавать только администратор);
- Получение списка всех счетов;
- Получение счетов определенного пользователя;
- Возможность получать пользователей по фильтрам (цвету волос и полу);
- Получение информации о пользователе по логину.
  
## Примеры команд в Postman:
POST Вход в систему:
```
http://localhost:9090/auth/signin
```
В Body указывается логин и пароль в формате json. После идентификации и аутентификации надо скопировать jwt и вставить его в поле в разделе Authorization => Bearer Token, после чего сделать еще раз POST запрос для авторизации

Функционал, доступный авторизованному клиенту:

1) GET (получение информации о себе):
```
http://localhost:9090/api/gateway/client/get-info-about-client
```
3) GET (получение данных о своих счетах)
```
http://localhost:9090/api/gateway/client/my-accounts
```
4) GET (получение своего счёта по ID)
```
http://localhost:9090/api/gateway/client/my-account-by-id/{id}
```
`id` - идентификатор счёта (задается самим пользователем)
5) GET (получение списка друзей со списками их счетов)
```
http://localhost:9090/api/gateway/client/friends-with-accounts
```
6) PUT (добавление в друзья)
```
http://localhost:9090/api/gateway/client/add-friend/{friend_login}
```
7) PUT (пополнение счёта)
```
http://localhost:9090/api/gateway/client/my-account/{account_id}/deposit?amount=XXX
```
8) PUT (снятие денег)
```
http://localhost:9090/api/gateway/client/my-account/{account_id}/withdraw?amount=XXX
```
9) PUT (перевод)
```
http://localhost:9090/api/gateway/client/{sender_account_id}/transfer/{target_account_id}?amount=XXX
```
10) DELETE (удаление друга)
```
http://localhost:9090/api/gateway/client/delete-friend/{user_login}
```
Функционал, доступный админу
1) POST (создание пользователя)
```
http://localhost:9090/api/gateway/admin/create-user
```
пример для Body:
```
   {
        "login": "TypicalUser",
        "password": "j_002cs",
        "role": "CLIENT",
        "name": "John",
        "gender": "male",
        "hairColor": "brown",
        "age": 27
    }
```
2) GET (получение всех счетов)
```
http://localhost:9090/api/gateway/admin/get-all-accounts
```
3) GET (получение всех счетов пользователя по логину)
```
http://localhost:9090/api/gateway/admin/get-accounts-by-login/{user_login}
```
4) GET (фильтрация пользователей по цвету волос и полу)
```
http://localhost:9090/api/gateway/admin/filter?gender={male/female}&color={fair/dark/brown}
```
- Если нужно фильтровать только по одному параметру, то его указывать не надо (то есть gender= — если не надо фильтровать по полу)
5) GET (получение информации о пользователе по его логину)
```
http://localhost:9090/api/gateway/admin/get-info-about-user/{user_login}
```

POST Выход из системы:
Перед выполнением надо убрать из поля jwt
```
http://localhost:9090/auth/logout
```
